## 자식 에이전트 — 실제 일감은 spawn, 일회성 실행은 서브에이전트

이 묶음에서 두 용어를 구분한다.

- **자식 세션**: claunch MCP `spawn` 도구로 만든 세션이다. 자기 터미널, 자기
  보드 이슈, 메시 멤버십을 가지며 부모가 `kill`로 끝낼 때까지 남는다.
- **서브에이전트**: 하네스의 에이전트 도구(Claude Code의 `Agent`/Task,
  `general-purpose` 타입 등)로 띄운 실행이다. 부모 세션 안에서 돌고, 같은
  `CLAUNCH_SESSION`을 쓰며, 결과 한 덩어리를 돌려주면 끝난다.

워크플로 정본에서 「spawn한 subagent」라고 적은 것(스윕·머지 실행)은 두 번째,
서브에이전트를 가리킨다.

### 실제 일감을 맡길 때: 자식 세션

다음 중 하나라도 해당하면 자식 세션을 만든다.

- 코드·문서를 고치고 커밋하는 일, 보드 이슈 하나를 처리하는 일
- 중간에 질문·판단·재지시가 오갈 수 있는 일
- 결과를 보드에 남기고 이후 다른 세션이 이어받아야 하는 일

절차:

1. `children`으로 남은 슬롯과 선택할 수 있는 필드를 확인한다.
2. `spawn`으로 만든다. `handle`·`role`·`task`를 주고, 코드를 고치는 자식에게는
   `worktree`(이름 앞에 세션 이름)를 준다. 미리 써 둔 이슈가 있으면 `issue`로
   넘겨 중복 이슈가 생기지 않게 한다. `mesh`·`workflow`는 생략한다
   (`mesh` 스킬의 Step 4). role이 reviewer가 아니면 spawn은 사람의 승인을
   기다린다: 응답은 `pending`과 요청 id이고, 만들어진 세션 이름은 터미널에 오는
   `[claunch spawn-request <id>]` 블록에 있다. 그 블록을 받기 전에는 3·4를
   하지 않고 같은 일로 다시 spawn하지 않는다. 거절이면 자식 없이 진행한다.
3. 소통은 claunch MCP `send` 도구로 한다. 여러 자식에게 서로 다른 지시를 줄 때는
   `sections`로 한 번에 보낸다. 지시는 `say`/`ask`로 보내고, 상태 알림만
   `fyi`/`ack`로 보낸다.
4. 일이 끝나면 결과를 보드에서 확인한 뒤 `kill`로 자식을 끝낸다.

자식 세션의 일을 서브에이전트에 맡기지 않는다. 서브에이전트는 메시에 없어서
도중에 묻거나 답할 수 없고, 보드 기록과 자기 체크아웃이 없으며, 부모의 턴이
끝나면 그 맥락도 남지 않는다.

### 일회성 비동기 실행: 서브에이전트

다음은 서브에이전트(`general-purpose` 등)로 실행한다.

- 머지 실행, 전체 스윕·테스트 실행처럼 명령을 돌리고 해시·수치를 가져오는 일
- cflow v2 런이 `executor: subagent`로 위임한 노드(flow_status의 `delegations`에
  있는 brief) — brief만 주고 실행하며 결과는 `flow_delegate`로 제출한다
- 코드 검색처럼 결론만 필요한 조회

이 경우에도 한 서브에이전트에는 한 가지 일만 맡긴다. 서브에이전트는 부모와 같은
`CLAUNCH_SESSION`으로 돌기 때문에 targeted 테스트 창을 부모와 함께 쓴다. 여러
서브에이전트에 pytest를 나눠 맡겨도 동시에 도는 실행은 하나뿐이다.

### 다른 규칙과의 관계

- 역할 팩이 자식 생성을 금지하면(예: `role-analyst`) 그 금지를 따른다.
- `claunch new-session`은 사용자의 명령이다. 세션 안에서는 쓰지 않는다.
- 이 묶음은 자식을 만들어야 할 때 어느 도구를 쓰는지를 정한다. 자식을 만들지 말지는
  `mesh` 스킬과 역할 팩의 기준으로 판단한다.
- `mesh` 스킬은 CLI `claunch mesh send`와 MCP `send`를 함께 안내한다. MCP 도구를 쓸
  수 있는 세션에서는 이 묶음에 따라 MCP `send`를 쓴다. 두 경로는 같은 메시 채널로
  전달된다.
